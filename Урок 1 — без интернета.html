Шаг 3. Проверка ответа модели — главная часть

Зачем: модель должна вернуть JSON вида {"category": "spam", "confidence": 0.9, "reason": "..."}. Но иногда она возвращает лишний текст, неизвестную категорию или вообще ерунду. Хорошая система не угадывает, а отдаёт такие случаи человеку. Это твой принцип «получено = обработано», только в коде.

В classifier.py:

CATEGORIES = ["customer_enquiry", "existing_customer", "sales_pitch", "supplier", "spam", "other"]
THRESHOLD = 0.7

def parse_decision(raw):
    """Принимает текст от модели, возвращает словарь:
    {"category": ..., "confidence": ..., "reason": ..., "needs_human": True/False}"""
    ...
Задание 3.1 Правила:
  1. Если JSON нормальный и категория из списка → вернуть её; needs_human = confidence < THRESHOLD.
  2. Если вокруг JSON есть лишний текст (Sure! {"category": ...}) → всё равно найти JSON между первой { и последней }.
  3. Если JSON сломан или нет нужных полей → category="other", confidence=0, needs_human=True.
  4. Если категории нет в списке → то же самое: other + человеку.
  5. Если confidence больше 1 или меньше 0 → обрезать до 1 или 0.
Подсказка 1 — как найти JSON в тексте 
start = raw.index("{")        # позиция первой {
end = raw.rindex("}") + 1     # позиция после последней }
data = json.loads(raw[start:end])
index выбросит ошибку ValueError, если скобки нет. json.loads тоже выбрасывает ValueError на сломанном JSON.
Подсказка 2 — как ловить ошибки 
try:
    ...  # всё, что может сломаться
except (ValueError, KeyError, TypeError):
    return {"category": "other", "confidence": 0.0, "reason": "unparseable", "needs_human": True}
KeyError — когда в словаре нет ключа "category". TypeError — когда confidence не число.

Шаг 4. Автотесты

Зачем: тест — это маленькая программа, которая проверяет твою функцию. Изменишь код — запустишь тесты и за секунду узнаешь, что ничего не сломала. В Provectus это обязательное требование.

В test_classifier.py:

import unittest
from classifier import parse_decision

class TestParseDecision(unittest.TestCase):

    def test_valid_output(self):
        result = parse_decision('{"category": "spam", "confidence": 0.9, "reason": "phishing"}')
        self.assertEqual(result["category"], "spam")
        self.assertFalse(result["needs_human"])

if __name__ == "__main__":
    unittest.main()

Запуск: python -m unittest -v

Задание 4.1 Допиши ещё 5 тестов — по одному на каждое правило из шага 3: JSON с лишним текстом · низкая уверенность (0.4) → человеку · полная ерунда («I cannot help») · неизвестная категория («urgent») · confidence = 7 → становится 1.0.
Цель: 6 тестов, все OK.
Полезно специально сломать код (например, поменяй < на >) и посмотреть, какой тест упадёт. Так ты увидишь, что тесты реально ловят ошибки. Потом верни как было.

Задание 5.1 В classifier.py напиши fake_model(subject, body), которая возвращает строку JSON, решая по ключевым словам:
«quote», «install», «how much» → customer_enquiry · «leads», «loan», «fee» → sales_pitch · «order», «dispatched» → supplier · «invoice», «visit» → existing_customer · «verify», «suspended» → spam · иначе other с confidence 0.3.
Задание 5.2 Напиши classify(subject, body, model=fake_model): вызывает модель, передаёт её ответ в parse_decision, возвращает результат.
Параметр model — это и есть то место, куда завтра подставим настоящего Claude.

Подсказка — f-строки

print(f"Accuracy: {correct}/{total} = {correct / total:.0%}")
Главный вывод урока. Посмотри, на каких письмах фальшивая модель с ключевыми словами ошиблась. Скорее всего это твои хитрые письма из задания 1.1. Ровно поэтому у Люка нужен AI, а не фильтр по словам. Завтра подставим Claude и сравним точность — это и будет твоя история для собеседования: «ключевые слова дали X%, LLM — Y%, вот на каких случаях разница».
